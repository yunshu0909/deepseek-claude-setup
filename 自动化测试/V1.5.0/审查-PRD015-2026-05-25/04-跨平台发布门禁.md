## 2. 阻断级发现

### [P0] F-01 真实 Mac 报告会被 provenance 校验误杀，正式 gate 当前无法通过

**影响**：即便后续取得 clean Mac 报告，当前门禁也会把真实 Darwin 运行判为来源冲突；release 流程不可执行。

**证据**：

- 平台采集器将 `osRelease` 写为 `os.release()`，真实 Mac 报告实际值为 `"25.2.0"`：`scripts/certification/platform-context.js:70-72`；`reports/provider-certification/deepseek-darwin-2026-05-25T11-12-10-094Z/report.json:20-27`。
- 门禁却要求 Darwin 的 `osRelease` 匹配 `/Darwin/i`：`scripts/certification/release-gate.js:41-47`。
- 单测 fixture 手写 `"Darwin 25.0.0"`，未使用采集器的真实 Darwin 输出，因而未捕获此错误：`test/certification.test.js:57-62,143-147`。
- 只读探针：对现有 Mac 报告运行 `npm run certify:release -- <report.json>`，除正确命中 `worktree is dirty` 外，还错误返回 `platform provenance conflicts with expected platform`。

### [P0] F-02 gate 不绑定待发布 commit，三份同样过期的报告可以放行

**影响**：三平台即便都测的是旧提交，也可被用于发布后续未测代码，未满足“目标分支/commit”发布门禁。

**证据**：

- `expectedCommit` 未绑定当前待发布 HEAD，而是默认取输入第一份报告的 `commit`：`scripts/certification/release-gate.js:125-159`。
- 命令行入口只解析 `--provider=` 与报告文件参数，没有 `--expected-commit`，也没有读取当前发布 checkout 的 HEAD：`scripts/certification/release-gate.js:163-175`。
- `TC-055`/release self-check 只覆盖 wrong branch、缺 provenance、重复 runner，不覆盖“三报告同为错误旧 commit”：`scripts/certify-provider.js:540-624`；`test/certification.test.js:184-202` 仅覆盖报告之间 commit 不一致。
- 只读内存探针将三平台报告统一设为 `commit="stale-but-shared"` 后，`evaluateReleaseGate()` 返回 `passed=true` 且 `expectedCommit="stale-but-shared"`。

### [P0] F-03 provenance 不是防复制证明：复制报告同步改字段即可通过

**影响**：当前实现能拦“只改 `platform`”的粗糙复制，不能阻止把一份结果改成三份平台报告；TC-055 的核心目标没有落地。

**证据**：

- gate 读取普通可编辑 JSON，只校验字段存在、路径/字符串外观和 `runnerId` 不重复，无签名、manifest hash、平台侧签章或受控收集渠道：`scripts/certification/release-gate.js:31-53,56-118,125-160`。
- `runnerId` 自身为报告生成时的随机字符串，报告被复制后同样可编辑：`scripts/certification/platform-context.js:60-80`。
- 测试只把 Mac context 的 `platform` 改为 `win32`，未测试同时修改 `osRelease`、`nodeExecPath` 与 `runnerId` 的复制报告：`test/certification.test.js:177-182`。
- 同一只读内存探针用自洽的 Darwin/Win32/Linux 外观字段及不同 `runnerId` 构造复制报告，gate 返回 `passed=true`。

## 3. 高风险缺口

### [P1] F-04 跨机器报告的 evidenceRefs 不可移交，三平台真实汇总路径未闭合

**影响**：Windows/Linux 在各自机器生成报告后，把 `report.json` 交给另一台 release-gate 主机时，其本机绝对 evidence 路径不可读；gate 会拒绝真实报告。当前没有可携带证据包或相对路径导入约定。

**证据**：

- 认证器和 client runner 将本机绝对路径直接写入 `evidenceRefs`：`scripts/certify-provider.js:83-87,210-237,447-460`；`scripts/client-e2e.js:749-775`。
- gate 要求每个 PASS 用例的每个 `evidenceRefs` 都在 gate 所在文件系统上 `fs.existsSync()` 可读：`scripts/certification/release-gate.js:50-53,82-96`。
- 现有 Mac 报告的引用均为 `/Users/yunshu/.../evidence/...` 绝对路径：`reports/provider-certification/deepseek-darwin-2026-05-25T11-12-10-094Z/report.json:78-107`（其余用例同形态）。
- PRD 要求报告来自三个各自真实环境并交给 release gate 汇总：`PRD-015-v1.5.0-provider-certification.md:67-83,203-226`。

### [P1] F-05 Linux Hermes 有 runner 入口，但 TC-044 真场景证据尚未执行且 PASS 断言缺关键链路证明

**影响**：Linux/Hermes 不能作为已认证发布证据；即使将来 runner 返回 PASS，目前产物也不足以复核 Hermes 是否经本轮 transient gateway 完成请求。

**证据**：

- TC-044 要求 Linux 真 Key、systemd active、`HERMES_OK`、日志无 Key，并产出 `systemctl status` 摘要与 Hermes 脱敏日志：`PRD-015-v1.5.0-provider-certification-测试用例.md:760-774`。
- 实现确有 Linux 本机专用入口与 transient systemd/Hermes 执行路径：`scripts/certify-provider.js:463-480`；`scripts/certification/linux-hermes-smoke.js:20-53,61-110`。
- 但 PASS 仅检查 `systemctl is-active` 输出、health 文本、`HERMES_OK` 和 config diagnostic；脚本只对 gateway log 做不泄密 grep，未要求或保存本轮 `CHAT_DONE`/请求完成日志，也未采 `systemctl status` 摘要：`scripts/certification/linux-hermes-smoke.js:46-52,90-109`。
- 既有测试只断言生成的 shell 文本包含若干关键词，不运行 Linux/systemd/Hermes 真场景：`test/certification.test.js:391-409`。
- 当前测试报告明确承认 Linux 真场景未执行：`自动化测试/V1.5.0/TEST_REPORT.md:45-49`；当前 reports 下也只有 `deepseek-darwin-*` 目录。

### [P1] F-06 Windows 只有通用 runner 代码路径，没有已证明可执行的真实自动化路径

**影响**：不能据代码存在宣称 Windows 认证可执行或已覆盖；Claude 工具/长任务路径还包含未声明、未预检的 Bash 依赖。

**证据**：

- 入口对 Windows 的明确适配仅见 `npm.cmd` 和临时 HOME 变量：`scripts/certify-provider.js:72-80`；`scripts/client-e2e.js:95-104`。
- true-key preflight 仅检查 `claude`/`codex` CLI 与 flags，不检查 Windows 上 Bash/Git Bash 是否存在：`scripts/client-e2e.js:362-390`。
- 实际 Claude 工具与长任务会强制开放 `--tools=Bash`，长任务 prompt 还要求 “Bash heredoc”：`scripts/client-e2e.js:26-34,428-441,515-537`。TC 的 Windows 规则未将此依赖作为前置条件：`PRD-015-v1.5.0-provider-certification-测试用例.md:11-24,250-296,659-676`。
- 当前 TEST_REPORT 明确写明 Windows release-ready 报告未执行：`自动化测试/V1.5.0/TEST_REPORT.md:47-49`。

## 6. 发版仍缺的真实证据

1. 将认证实现纳入一个明确的发布候选 commit 后，在 **clean macOS worktree** 上重新生成完整 true-key 报告；当前报告绑定 `aad165c` 且记录了尚未提交的 `scripts/` 与测试改动：`reports/provider-certification/deepseek-darwin-2026-05-25T11-12-10-094Z/report.json:3-15`。
2. 在真实 Windows 环境、同一候选 commit 上取得完整 P0/true-key 报告，并证明 Claude/Codex 工具及长任务路径确实可运行；目前只有未实跑代码。
3. 在真实 Linux 服务器、同一候选 commit 上取得完整报告，并以 `--target hermes-linux` 完成 `TC-044`；证据必须保留 transient systemd 状态摘要和经本轮 gateway 的脱敏完成日志。
4. 取得可由统一 release gate 消费的三平台证据包或可信汇总方式，避免 source-host 绝对路径在汇总主机失效。
5. gate 修复后补充反证回归：真实 `collectPlatformContext()` Darwin 报告可通过 provenance；三份同样错误 commit 被拒；复制报告即使同步改外观字段也无法冒充。

## 8. 最终判定

**Release gate：FAIL。** 缺 clean Mac、Windows、Linux/TC-044 三平台真实证据已经足以阻断发布；此外 F-01 至 F-04 表明当前 gate 既会拒绝真实 Mac 报告，也无法可靠阻止旧 commit 或字段改写后的复制报告，尚不能承担 PRD-015 所要求的正式发布门禁。
